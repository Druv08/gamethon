# Protect the King — 2D

Top-down / three-quarter pixel-art action game. Unreal Engine **5.8**, **Paper2D**,
**Enhanced Input**, gameplay core in **C++**.

> **Status: Phase 1 — reusable 2D character movement system.**
> Ravager only. Idle + Walk, four directions. No combat.

### Installing the C++ toolchain

This is a **C++** Unreal project, so it cannot be opened or compiled until a
Microsoft C++ toolchain is present. Install either:

- **Visual Studio 2022 Community** — <https://visualstudio.microsoft.com/downloads/>, or
- **Build Tools for Visual Studio 2022** (compiler only, no IDE)

In the Visual Studio Installer, select these workloads/components:

- ☑ **Desktop development with C++**
- ☑ **Game development with C++**
- ☑ **Windows 11 SDK** (any recent 10.0.2xxxx version)
- ☑ **MSVC v143 — VS 2022 C++ x64/x86 build tools**

Verify afterwards:

```powershell
& "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -latest -property displayName
```

An empty result means the toolchain is still missing.

## Regenerating game assets

All Phase 1 sprites, flipbooks, input assets and the test level are generated by one
script, so they can always be rebuilt from source PNGs:

```powershell
& "C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" `
    "$PWD\ProtectTheKing2D.uproject" `
    -run=pythonscript -script="$PWD\Tools\PTK_GenerateAssets.py" `
    -unattended -nosplash -nullrhi
```

Or inside the editor: **Window → Output Log**, switch the input box to **Python**, and run

```python
exec(open(r"<ProjectDir>/Tools/PTK_GenerateAssets.py").read())
```

The script is **idempotent** — re-running it updates existing assets in place. It ends
with a verification pass that checks pivots, filtering, flipbook frame counts and input
bindings, and reports `ALL CHECKS PASSED` or the specific failures.

## Art pipeline

```
PNG frames  →  Textures  →  Paper Sprites  →  Paper Flipbooks  →  PaperFlipbookComponent
```

Source art lives outside `Content/`, in `ArtSource/`:

| Folder | Purpose |
|---|---|
| `ArtSource/Characters/Guards/Ravager/Frames/` | **Final** Ravager frames (currently empty) |
| `ArtSource/Characters/Guards/Ravager/Concept/` | Concept art — reference only, never imported |
| `ArtSource/_TempDevArt/Ravager/` | **Temporary** developer placeholders |

The generator prefers `Frames/` and only falls back to placeholders when the final 20
frames are not all present. **Dropping the final art in and re-running the script is the
entire swap procedure.**

Placeholders are produced by a standard-library-only script:

```powershell
python Tools\GeneratePlaceholderFrames.py
```

It refuses to emit frames whose feet do not land on the anchor row, so the pivot
contract is machine-checked rather than trusted.

**The full art contract is [`Docs/SPRITE_SPEC.md`](Docs/SPRITE_SPEC.md)** — read it before
producing frames for any of the 11 characters.

## Architecture

```
ACharacter
   └── APTKTopDownCharacter      ← all movement, facing, animation, input, camera
          └── APTKGuardCharacter ← playable-guard tier
                 └── BP_Ravager  ← assets + tuning values only
```

`APTKTopDownCharacter` is the **only** implementation of 2D movement in the project.
Adding a character never means writing movement code — it means making a Blueprint and
filling in eight flipbooks. That applies to all of Ravager, King, Aegis, Wraith, Reaver,
Sentinel, Swarm Node, Infiltrator, Hijacker, Encrypter and Exfiltrator.

| File | Contains |
|---|---|
| `Source/ProtectTheKing2D/Public/Core/PTKTypes.h` | `EPTKFacingDirection`, `EPTKMovementState`, `FPTKDirectionalFlipbooks` |
| `Source/ProtectTheKing2D/Public/Characters/PTKTopDownCharacter.h` | The reusable character |
| `Source/ProtectTheKing2D/Public/Characters/PTKGuardCharacter.h` | Guard tier |
| `Source/ProtectTheKing2D/Public/Core/PTKGameModeBase.h` | Default pawn wiring |

### World convention

This is a **genuine 2D game** — the three-quarter look is in the artwork, not in a tilted
3D camera.

| | |
|---|---|
| Play plane | world **XZ** |
| Screen right | `+X` |
| Screen up | `+Z` |
| Depth axis | `Y` (constrained; smaller Y draws in front) |
| Camera | orthographic, at `-Y`, looking along `+Y` |
| Gravity | **none** — `GravityScale = 0`, `MOVE_Flying`, plane-constrained |
| Scale | **1 pixel = 1 Unreal unit** |

Sprites are **never rotated** to show direction — direction is only ever a flipbook swap.
